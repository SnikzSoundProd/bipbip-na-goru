# «БИП БИП НА ГОРУ» — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Кооп-игра на 2 игрока в стиле PEAK: два регдолл-человечка лезут на процедурную гору, хватаясь за всё двумя руками. Полностью свой C++ движок на DX11, сеть на GameNetworkingSockets (клиент-хост, как TF2).

**Architecture:** Свой движок `bipbip-engine` (статическая либа) + тонкий exe игры. Модули: платформа/ввод → DX11 рендер → Jolt физика → сетевой слой GNS (client-host, dedicated listen server) → генерация горы из сида → геймплей (персонажи, хватание, стамина). ECS не нужен — простые структуры + фиксированный тик 60 Гц с интерполяцией на рендере.

**Tech Stack:** C++20, mingw-w64 GCC 16.2 (`C:\msys64\mingw64`), DX11 (заголовки и import-либы уже в mingw64), D3DCompiler_47 (runtime-компиляция шейдеров), Jolt Physics (git clone, собирать тем же GCC), GameNetworkingSockets 1.6.0 (`C:\Users\apex\Downloads\GameNetworkingSockets-1.6.0`, `USE_CRYPTO=BCrypt`), CMake (portable zip, pacman сломан), SDL2 уже стоит в msys64 но НЕ используем — ввод через Raw Input + WinAPI окно.

**Решения принятые за пользователя (он ответил «хз»):**
- Гора: гибрид — процедурная из сида, но собранная из авторских биомных модулей, чтобы маршрут всегда был проходимым.
- Управление: PEAK-style — WASD+мышь, ЛКМ/ПКМ = левая/правая рука хватают ближайшее в конусе.
- Первый майлстоун: вертикальный срез (движение+регдолл+хватание на одной горе), сеть вторым этапом.
- Название: **«БИП БИП НА ГОРУ»**, кодовое имя проекта `bipbip`.
- Без мета-прогрессии: забег → статистика → новый сид.

## Phase 4: Сеть (client-host, GNS)

### Task 4.1: Сетевой каркас
**Objective:** Абстракция NetLayer поверх GNS: host создаёт listen socket на 27015, клиент connect по IP. Пакеты: InputState (20 Гц), WorldSnapshot (20 Гц), Events (надёжно).

**Files:**
- Create: `engine/net/net_manager.cpp/.h`
- Create: `engine/net/protocol.h` — версии, ID сообщений, сериализация (ручная, little-endian, memcpy POD структур с static_assert(sizeof))

**Model:** Как TF2 client-host: хост = сервер+клиент в одном процессе. Симуляция живёт у хоста; клиент шлёт инпут, получает снапшоты, интерполирует чужого игрока между снапшотами (100ms буфер), своего — предсказание локально + reconciliation по последнему подтверждённому состоянию.

### Task 4.2: Синхронизация персонажа
**Objective:** Второй человечек появляется у клиента, оба видят движения друг друга.

**Files:**
- Modify: `engine/net/*`, `game/player/*`

**Details:** Персонажи — единственные динамические тела с полной синхронизацией (pos+quat+linvel, 20 Гц, снап при ошибке > 2м). Регдолл-джоинты НЕ синхронизируются — каждый клиент симулирует чужой регдолл как «puppet» (упрощённый: одна капсула + визуальный регдолл на пружинах). Это ключевое упрощение против рассинхрона.

### Task 4.3: Синхронизация grabbed objects
**Objective:** Общие физические объекты (камни, ящики) толкаются обоими.

**Details:** Ownership-модель: объект принадлежит последнему тронувшему, владелец шлёт состояние, остальные следуют. Grab другого игрока его же клиентом — приоритет владельца.

### Task 4.4: Лобби и UI подключения
**Objective:** Главное меню: «Хостить» / «Подключиться» (IP-поле). Прогресс загрузки горы (сид передаётся в handshake).

**Files:**
- Create: `game/ui/menu_state.cpp/.h` (IMGUI рисуем сами: quad + шрифт-атлас из BMP, YAGNI на внешние либы)

**MILESTONE 2 ГОТОВ:** дуо-кооп работает по сети.

## Risks / Tradeoffs
1. **GNS под mingw** — главный технический риск (Task 0.3). Фолбэк-цепочка: патчи → clang-cl → (крайне) enet-замена. Решать в первый же день.
2. **Регдолл-балансировка** — PD-тюнинг может съесть 2-3 дня. Смягчение: сначала «жёсткий» режим (капсула-контроллер), регдолл включается при оглушении/хватании — так делают многие слопы.
3. **Сеть регдоллов** — полное решение дорого; принято упрощение puppet-тел (см. 4.2).
4. **DX11 без SDK** — заголовки mingw иногда отстают (нет свежих DXGI enum). Не критично для базового пайплайна.
5. **Gemini Lake слабый** — бюджет кадра 16.6мс: физика ≤6мс, рендер ≤6мс. Профилировать с Task 1.2, не в конце.
