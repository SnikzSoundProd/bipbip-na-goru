# БИП БИП НА ГОРУ

Кооперативная игра про восхождение на гору для двух игроков, в духе *PEAK*, написанная **полностью с нуля на C++** — свой движок (DirectX 11), своя физика (verlet-солвер), своя сеть (GameNetworkingSockets) и собственный **редактор уровней** в стиле Unreal.

> Ни Unity, ни Unreal, ни готовых библиотек физики. Всё — от окна Win32 до ragdoll-физики — написано руками.

## Игра

Два регдолл-альпиниста лезут на процедурную гору. Гора генерируется из **сида**, поэтому у обоих игроков она **одинаковая** — это основа кооператива.

Что есть:

- **Ragdoll-персонаж** — 13 частиц на verlet-констрейнтах, полукинематический таз, руки/ноги — чистый ragdoll
- **Физические зацепки** — можно хвататься двумя руками (ЛКМ/ПКМ) за holds на скале
- **Стамина** — висишь → тратишь, стоишь → восстанавливаешь. Если обнулилась — руки разжимаются
- **Травмы и падения** — упал ниже последней безопасной точки → респавн, счётчик падений растёт
- **Чекпоинты** — большие оранжевые holds, запоминают точку возрождения
- **Вершина** — дойдёшь до пика → экран победы со временем и числом падений
- **Общие ящики** — физические объекты, которые может толкать любой игрок; симуляция **host-authoritative**
- **Кооператив 2 игрока** — модель client-host (как в TF2): хост — авторитетный сервер, второй игрок подключается

### Сеть

- Транспорт: **GameNetworkingSockets** (Valve), статическая линковка с `BCrypt`
- Модель: **client-host** — хост симулирует мир, клиент шлёт только input
- Частоты: физика **60 Гц** (fixed step), сеть **20 Гц** (input/snapshot)
- **Local prediction + reconciliation** — клиент предсказывает движение локально, хост присылает авторитетную позицию, клиент мягко подтягивается (при расхождении > 3 м — жёсткий респавн)
- В снапшот уходят: полная поза ragdoll (13 точек), трансформы ящиков, ownership, ack-последовательности

## Редактор

`bipbip_editor.exe` — **отдельный легковесный редактор** (ImGui, docking branch), который при этом использует **тот же самый игровой код**, что и игра.

### Разделение Сцена / Игровое состояние (как в Unreal)

| | Что это | Где живёт |
|---|---|---|
| **Сцена** | Авторские данные: ящики, holds, сид горы, спавн | `Scene`, сериализуется в `assets/scenes/*.bipscene` |
| **Игровое состояние** | Рантайм: позиции, скорости, стамина, физика | `PIEWorld`, создаётся при Play, уничтожается при Stop |

Редактор правит **сцену**. При нажатии **Play** создаётся PIE-мир из **снапшота** сцены — поэтому правки во время игры **не портят** сохранённый уровень.

### Панели

- **Outliner** — список ящиков и holds, кнопки `+ Box` / `+ Hold` / `Delete`
- **Details** — трансформы выбранного объекта (позиция, размеры, поворот в градусах, чекпоинт)
- **Settings** — **все тюнинги игры** через GUI (см. ниже)
- **Viewport** — 3D-вид с picking и навигацией

### Возможности

- **Play / Stop (PIE)** — играть прямо в редакторе, без отдельного билда
- **Плавный fly-to камеры** (ease-in-out, 0.85 с) при клике по объекту в Outliner или во viewport (как клавиша **F** в Unreal)
- **WASD + Space + хватания** прямо в редакторе
- **Drop to Ground** — посадить объект на поверхность горы по `heightAt()`
- **Hot-apply** — применить изменения сцены в запущенную игру **без перезапуска** (Unreal так не умеет)
- **Pick & focus** — клик в viewport выбирает объект и подлетает к нему
- **HUD и F3-профайлер идентичны игровым** — общий модуль `game/hud/hud_overlay.cpp`

### Settings — настройка игры без копания в код

Все значения лежат в **`assets/config/game.cfg`** и крутятся ползунками:

| Секция | Параметры |
|---|---|
| **Camera** | chase distance, height offset, pitch, fov Y, sensitivity, лимиты pitch |
| **Physics** | fixed dt, max substeps, пороги сна (linear/angular/delay) |
| **Gameplay** | grab reach, fall distance, stamina за хват, число сегментов HUD |
| **Network** | port, send rate (Hz) |
| **HUD** | x, y, scale |
| **World** | seed, world size, разрешение heightfield |

Кнопки **Save Config** / **Reload** / **Defaults**. Игра и редактор читают **один файл** — рассинхронизация невозможна.

## Движок

Собственный, без внешних игровых библиотек.

| Подсистема | Что сделано |
|---|---|
| **Платформа** | Win32-окно, raw input, pump сообщений, хук для ImGui |
| **Рендер** | DirectX 11: swapchain, depth buffer (`D24_UNORM_S8_UINT`), runtime-компиляция HLSL, constant buffers (PerFrame/PerObject/Tint), меши, инстанс-подобная отрисовка через world-матрицы |
| **Камера** | Своя `viewProj`, извлечение **6 плоскостей frustum** (точный вывод для column-major HLSL) |
| **Culling** | Frustum-culling динамических объектов (ящики, holds, ragdoll) со счётчиком draw calls |
| **Физика** | Свой **verlet-солвер**: частицы, констрейнты, OBB, импульсы, трение Кулона, инерция, **сон объектов** (sleep) |
| **Мир** | Процедурный heightfield с ridged noise, детерминированный по сиду |
| **Текст/HUD** | Свой `TextRenderer` (батчинг вершин, орто-проекция), общий HUD-модуль |
| **Ассеты** | Загрузчик `.obj`, текстуры через WIC, файл-вотчер для hot-reload, `AssetManager` с кэшем |
| **Сеть** | `NetLayer` над GameNetworkingSockets, протокол со счётчиками пакетов |
| **Конфиг** | `GameConfig` — единый источник тюнингов |

### Физика: сон объектов

Покоящиеся тела засыпают и перестают считаться. Важная деталь: позиционная коррекция (Baumgarte) **вкачивала энергию**, из-за чего `angVel` вечно oscillated и объект **никогда не засыпал**. Лечится демпфированием на малых скоростях (не трогая нормальное качение по склонам) — это подтверждено тестом `PHYSICS_SLEEP_TEST_PASS`.

## Сборка

Требования: Windows, MinGW-w64 (GCC 16.2), CMake 3.24+, Ninja, Windows SDK (D3D11).

```bash
export PATH="/c/Users/apex/bipbip/tools/cmake-3.30.5-windows-x86_64/bin:/c/Users/apex/bipbip/tools:/c/msys64/mingw64/bin:/c/msys64/usr/bin:$PATH"

cd /c/Users/apex/bipbip/build
cmake -G Ninja ..
cmake --build .
ctest --output-on-failure     # 11/11 тестов, включая кооп smoke-тест
```

Это **единственная точка входа**: сборка игрa + редактора + всех тестов, затем прогон тестов. Ручные команды `g++` не нужны (разве что для отладки одного теста).

Соберутся три категории таргетов:

| Таргет | Что это |
|---|---|
| `build/game/bipbip.exe` | игра |
| `build/editor/bipbip_editor.exe` | редактор |
| `build/tests/*_test.exe` | 10 тестовых suite'ов + `coop_smoke` |

DLL MinGW (protobuf, libstdc++ и пр.) копируются рядом с каждым exe автоматически — общий helper `tools/runtime_dlls.cmake`, без дублирования в каждом `CMakeLists.txt`.

Зависимости (вендорятся):
- **Dear ImGui** (docking branch) — `thirdparty/imgui`, только для редактора
- **GameNetworkingSockets** — статическая сборка, `thirdparty/gns-build`
- **protobuf / abseil** — подтягиваются GNS

> Игра **не** линкует ImGui — её HUD рисуется собственным `TextRenderer`, поэтому shipped-билд остаётся легковесным.

## Запуск

### Игра

```bash
# Solo
build/game/bipbip.exe 1337

# Хост (сервер)
build/game/bipbip.exe 1337 --host

# Клиент
build/game/bipbip.exe --join 127.0.0.1
```

Без аргументов откроется **меню подключения** (Solo / Host / Join / Quit) со строгой валидацией IPv4 и показом ошибок.

### Редактор

```bash
build/editor/bipbip_editor.exe
# или с конкретной сценой:
build/editor/bipbip_editor.exe assets/scenes/default.bipscene
```

```
│   ├── physics/     # verlet-солвер
│   ├── world/       # heightfield
│   └── net/         # NetLayer + протокол
├── game/            # игра
│   ├── player/      # ragdoll-альпинист
│   ├── world/       # маршрут (holds)
│   ├── gameplay/    # стамина, чекпоинты, победа
│   ├── hud/         # общий HUD + профайлер (используется и редактором!)
│   ├── ui/          # меню подключения
│   └── main.cpp     # точка входа игры
├── editor/          # редактор
│   ├── editor_main.cpp
│   ├── pie_world.*  # PIE: игровое состояние редактора
│   └── camera_fly.h # плавные перелёты камеры
├── assets/
│   ├── config/      # game.cfg — все тюнинги
│   ├── scenes/      # *.bipscene — уровни
│   └── shaders/     # HLSL
└── thirdparty/      # imgui, gns-build
```

### Ключевой принцип: один код — два приложения

```
     bipbip_engine  (движок)
            ↑
     bipbip_game    (геймплей: climber, route, run, menu, hud)
        ↙        ↘
  bipbip.exe   bipbip_editor.exe
   (игра)        (редактор + ImGui)
```

Редактор линкует **ту же** `bipbip_game`, поэтому:

- физика в редакторе = физика в игре
- HUD в редакторе = HUD в игре (общий `hud_overlay.cpp`)
- конфиг один на двоих (`game.cfg`)

Никаких «копий для отладки», которые расходятся.

### Форматы данных

**`assets/config/game.cfg`** — простой `key = value`:
```
camera.distance = 6.5
camera.pitch = 0.32
physics.fixedDt = 0.0166667
gameplay.grabReach = 2.2
network.port = 27015
world.seed = 1337
```

**`assets/scenes/default.bipscene`** — текстовый уровень:
```
seed 1337
world 220 256
spawn 0 0 118
box 0 49.916 0  0.5 0.5 0.5  0 0 0  0
hold 0 14.4441 100  0
hold 3 16.8474 90  1
```

## Тесты

Большинство тестов — **автономные** (offline, без D3D), каждый запускается одной командой `g++`. Тесты редактора (`PIE`, `CLIMBER_VIS`) тянут D3D/GNS, поэтому они собираются через CMake вместе с редактором.

| Тест | Что проверяет | Запуск |
|---|---|---|
| `GAME_CONFIG_TEST_PASS` | Дефолты конфига = текущий тюнинг игры; round-trip сохранения | standalone |
| `SCENE_ROUNDTRIP_TEST_PASS` | Сериализация сцены без потерь | standalone |
| `SCENE_GROUND_TEST_PASS` | Объекты стоят **на** поверхности, а не под горой | standalone |
| `PHYSICS_SLEEP_TEST_PASS` | Ящик реально засыпает и не дрейфит | standalone |
| `FRUSTUM_TEST_PASS` | Плоскости frustum корректно отсекают | standalone |
| `CAMERA_FLY_TEST_PASS` | Плавные перелёты камеры (ease, точность попадания) | standalone |
| `ASSET_PIPELINE_TEST_PASS` | Загрузка `.obj` и файл-вотчер | standalone |
| *(menu, assert-based)* | Валидация IPv4 и переходы меню — через `assert()`, при успехе молча выходит с кодом 0 | standalone |
| `PIE_TEST_PASS` | Play/Stop/restart в editor без крашей | через CMake (нужен D3D/GNS) |
| `coop_smoke_test` | **Реальный кооп**: поднимает host + client и проверяет handshake на обеих сторонах | через CTest (PowerShell) |

### Запуск всех тестов

```bash
cd build
cmake -G Ninja ..
cmake --build .
ctest --output-on-failure
```

Ожидаемо: **100% tests passed (11 из 11)**.

> `coop_smoke_test` — это **настоящий** сетевой тест: он запускает два процесса игры (хост и клиент), даёт им соединиться и проверяет по логам, что **обе стороны** доложили о появлении buddy. Просто «два живых процесса» ничего не доказывали — см. раздел про баг с `--join` ниже.

Пример standalone-теста:

```bash
g++ -std=c++20 -I. -Iengine \
    engine/core/game_config.cpp engine/core/game_config_test.cpp -o /tmp/cfg && /tmp/cfg
```

### Примечание про smoke-тест

`NetLayer` использует **статический** указатель на инстанс, поэтому хост и клиент **не могут** работать в одном процессе — только два отдельных exe. Это совпадает с реальным деплоем, так что тест честный.

## Разбор: баг из-за которого сеть «молча» не работала

Показательный случай, найденный именно smoke-тестом.

Парсинг аргументов начинался со второго индекса:

```cpp
for (int i = 2; i < argc; ++i) {          // ← неверно
    if (!strcmp(argv[i], "--host")) ...
    else if (!strcmp(argv[i], "--join") ...)
}
```

При запуске `bipbip --join 127.0.0.1` (без сида) флаг `--join` — это `argv[1]`, а не `argv[2]`. Он **пропускался**, режим оставался `Solo`, и игра запускалась **без сети вообще** — при этом оба процесса выглядели «живыми и здоровыми».

`--host` работал только потому, что его запускали с сидом: `bipbip 1337 --host`, где `--host` попадал в `argv[2]`.

Фикс — сканировать с `1`, игнорируя нераспознанные аргументы (сид):

```cpp
for (int i = 1; i < argc; ++i) {
    if (!strcmp(argv[i], "--host")) netMode = NetMode::Host;
    else if (!strcmp(argv[i], "--join") && i + 1 < argc) { netMode = NetMode::Join; joinIp = argv[++i]; }
}
```

Плюс добавлен лог `[boot] netmode=...`, чтобы режим был виден сразу, и проверка `addr.ParseString()` в `NetLayer::join` (раньше неудачный парсинг давал нулевой адрес и «валидный» хендл, который никуда не соединялся).
